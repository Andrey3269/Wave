## 2. Изменения

### 2.1 OriginGuard (M7) — `backend/origin_guard.py`, подключение в `backend/main.py`

Чистый ASGI-middleware внутри TrustedHost и CORS. POST/PUT/PATCH/DELETE выполняются, только если `Origin` равен `http://<Host>` (Host уже проверен TrustedHost); чужой origin, `null`, другой порт или имя хоста, несколько разных `Origin` → **403** `{"detail": "Запрос с другого сайта отклонён.", "code": "forbidden_origin"}`. Без `Origin` отклоняется `Sec-Fetch-Site: cross-site | same-site`; запросы без браузерных заголовков (тесты, лаунчер) проходят. GET/HEAD/OPTIONS не затронуты (чтение по-прежнему ограничивает CORS). Разрешённых чужих origin нет: режим Live Server из `ALLOWED_ORIGINS` и раньше не мог выполнять изменяющие запросы (CORS — только GET, OPTIONS).

### 2.2 Валидация снимков трека (M6) — `backend/domain/snapshot.py`

- Единое определение формата id: `domain.models.TRACK_ID_RE` (резолвер потоков берёт его же).
- `TrackIn`/`KeyIn` (`userdata.py`): id не в формате источника → **422**; `stream_url` клиент присылает как раньше (контракт не менялся), сохраняется вычисленный сервером `/api/stream/{source}/{id}`; обложка — только `https://` с хостов обложек источников и их поддоменов (без логина и чужого порта) или `/api/local/{source}/{id}/cover`; публичная ссылка — `https://` на сайтах источников. Не прошедшие проверку обложка/ссылка сохраняются как `null`, трек не отклоняется.
- Чтение (избранное, история, плейлисты, рекомендации): строки пересчитываются через `read_snapshot`; недопустимые (не JSON, неизвестный источник, плохой id) пропускаются с записью в журнал, строка в базе остаётся. `DELETE` по ключу удаляет и такие строки (id с «/» от версий до S6).
- Тот же список — для очереди плеера (`playback.py`, раньше проходил любой `https://`), обложек миксов в настройках (раньше и `http://`) и скачивания обложки (`downloads.py`: проверка по окончанию имени пропускала `evilgoogleusercontent.com`).

### 2.3 Журнал (L1) — `backend/applog.py`

`redact()`: ссылки googlevideo целиком (узел CDN, путь, параметры), имена узлов googlevideo в текстах ошибок, логин:пароль в любых ссылках (прокси), значения параметров любых ссылок (имена остаются), строки Cookie/Set-Cookie, Bearer/Basic, секреты «ключ=значение» (добавлены `ip`, `pot`, `client_secret`, `api_key` и др.), IPv4/IPv6 кроме loopback. `RedactFilter` маскирует также трейсбеки (`exc_info` → `exc_text`) и `stack_info`. Консоль разработки (`uvicorn main:app`) получает тот же фильтр; `diagnostics._sanitize` использует `redact`.

### 2.4 N3 — пути из базы во всех файловых API

- `library.py`: строка индекса читается/удаляется, только если ключ совпадает с её источником и id, id в формате источника и папка — созданная загрузчиком Wave для этого трека (`… [источник-id]`). Закрыт найденный в S13 обход: строка с `root` на чужой каталог и обычной папкой (`root=C:\Users\Имя`, `folder=Documents`) раньше отдавала файлы. Файл-ссылка и файл, разрешающийся вне папки, не отдаются. Строки без `root` разрешаются по текущей папке загрузок без её создания.
- `/api/lyrics`: нечитаемый, не-JSON или неожиданного вида `lyrics.json` → текст из сети, а не HTTP 500.
- `settings.downloads_dir` из базы: допустим только абсолютный путь без управляющих символов, не указывающий на файл; иначе папка по умолчанию, строка не удаляется. `GET /api/settings` и `GET /api/downloads` больше не создают папку (`paths.current_downloads_dir()`), поэтому недоступная папка не даёт 500; загрузка в недоступную папку заканчивается ошибкой задачи, а не необработанным исключением фоновой задачи.

### 2.5 Редиректы при скачивании обложки (доработка) — `backend/downloads.py`

Закрыт риск из §5 первой версии отчёта: раньше общий HTTP-клиент сам следовал редиректам, и проверялся только исходный адрес. Теперь `_cover_response` выполняет редиректы вручную (`follow_redirects=False`), не больше `COVER_MAX_REDIRECTS = 3` переходов, и каждый адрес цепочки (исходный и каждый `Location`, в т.ч. относительный) проверяется заново: `https`, хост обложек источника или его поддомен с границей домена, без логина и чужого порта (`snapshot.safe_cover`), все IP имени публичные (`netguard.check_url`: не localhost, не частные сети, не link-local/метаданные облака). Запрос идёт клиентом `netguard.make_client` (как HLS): он повторно проверяет и закрепляет IP в момент соединения, поэтому подмена DNS между проверкой и запросом тоже не уводит в локальную сеть. Недопустимый адрес — трек сохраняется без обложки, как при любом сбое обложки. Тестовый двойник (`tests/wavetest/fakes.py`): хосты обложек «разрешаются» в публичный адрес, ответ обложки может быть своим (редирект).

## 5. Известные ограничения

- Счётчик треков в списке плейлистов (`GET /api/playlists`) считает и пропускаемые испорченные строки; на странице плейлиста их нет. Касается только строк, записанных мимо API.
- Обложка скачивается тем же клиентом с закреплением IP, что и HLS: при прокси пользователя типа `https://` или `socks` (туннель к IP-литералу невозможен) и в сети, где имя хоста не разрешается локально, обложка не скачивается — трек сохраняется без неё (как и прежде для HLS).
- `downloads_dir` и `root` могут быть UNC-путями (сетевой диск — допустимый выбор пользователя); проверка не обращается к сети, но чтение такой папки обращается.
- Защита от CSRF рассчитана на браузеры, присылающие `Origin`/`Sec-Fetch-Site` (Chromium, WebView2). Локальная программа без браузера по-прежнему может обращаться к API — это вне модели угроз этапа.
- Текстовые поля снимка (название, артисты) не фильтруются сервером; вывод во фронтенде — текстом (не менялось в S13).
- Ручная проверка на Windows 11 / WebView2 не проводилась (по заданию чек-лист не создавался); Windows покрыт CI.
