## 2. Что переиспользовано без переписывания

`backend/downloads.py` остался основой. Сохранены без изменения поведения:

- задача в памяти с опросом `/api/downloads/jobs`, состояния `preparing → downloading → processing → done | error`;
- аудио порциями по 4 МБ с `Range`, поддержка источника без Range (200) и неизвестного размера (`Content-Range */*`), перерезолв протухшей ссылки посреди загрузки;
- исходный формат без перекодирования (ffmpeg не нужен и не добавлен);
- обложка только с разрешённых https-хостов; текст из LRCLIB; пустой `lyrics.json` не создаётся;
- сборка папки в `*.part` и перенос целиком (`os.replace`), очистка `*.part` при старте;
- запись в SQLite (`library.add`), повторный запрос для скачанного трека → сразу `done`, повторный запрос для активной задачи → та же задача;
- имя папки `Artist - Title [source-id]`, защита от выхода имени за каталог загрузок;
- воспроизведение скачанного через тот же `/api/stream/{source}/{id}` с диска, без обращения к источнику.

## 4. Политика: что подтверждено и чем

| Утверждение | Чем подтверждено |
|---|---|
| yt-dlp 2026.08.19 извлекает `license` YouTube из строки «License» метаданных страницы | исходник `yt_dlp/extractor/youtube/_video.py` (`if mrr_title == 'License'`), его тестовые ожидания «Creative Commons Attribution license (reuse allowed)» и «Standard YouTube License» |
| Настоящий YouTube сегодня отдаёт эту строку | **не подтверждено**: LIVE-8a BLOCKED (§5) |
| У трека SoundCloud API v2 есть `downloadable`, `has_downloads_left`; файл — по `redirectUri` из `tracks/{id}/download` | исходник yt-dlp (`SoundcloudBaseIE._extract_info_dict`) и **LIVE-8b на настоящем SoundCloud**: `{"downloadable": true, "has_downloads_left": true, "license": "all-rights-reserved"}` |
| Без входа в аккаунт `tracks/{id}/download` отвечает 401 | **LIVE-8b**: HTTP 401 → `auth_required` |
| Тело запроса не может дать разрешение | `test_request_body_cannot_grant_permission` |
| Отсутствие поля `downloadable` не трактуется как разрешение | `test_soundcloud_missing_flag_is_not_assumed` → `permission_unknown` |

Коды отказов (окончательные — UI не предлагает повторить): `license_unknown`, `download_not_permitted`, `permission_unknown`, `download_limit_reached`, `auth_required`, `unsupported_format`. ## 6. Решения, которые остаются за владельцем

**6.1. YouTube: на практике загрузка будет отклоняться почти всегда.** Условия YouTube запрещают скачивание, кроме явно разрешённого сервисом или с разрешения YouTube и правообладателя. Возможность воспроизведения разрешением не считается. Единственный признак от правообладателя, который видит Wave, — лицензия Creative Commons; у официальных релизов YouTube Music её нет. Кроме того, не подтверждено (LIVE-8a), что YouTube по-прежнему отдаёт строку лицензии: если не отдаёт — все треки получат `license_unknown`. Варианты:

- **А (реализовано):** разрешать только Creative Commons, остальным — понятная причина. Честно, но кнопка для большинства треков покажет «Недоступно».
- **Б:** скрыть кнопку скачивания у треков YouTube совсем и показывать причину один раз в «Скачанных» — меньше разочарования, но та же функциональность.

Ни один вариант не возвращает «скачать любой трек YouTube»: это потребовало бы обхода условий сервиса, и в рамках правил проекта не делается.

**6.2. SoundCloud: признак работает, файл без входа не выдаётся.** LIVE-8b подтвердил: даже у трека с `downloadable: true` эндпоинт отвечает 401 без входа, поэтому загрузка закончится `auth_required` с понятным текстом. Минимальный способ устранить блокер — зарегистрированное приложение SoundCloud и вход пользователя по OAuth официального API. Это новая интеграция (регистрация, хранение токена без утечки в журнал и репозиторий, согласие пользователя, условия API), поэтому без отдельного решения владельца она не начиналась.

**6.3.** SoundCloud как источник (поиск, страницы, поток) в коде включён. Выключение по ADR-6 было частью прежней постановки S5, не реализовывалось и в новую постановку не входит.

## 7. Ограничения и остаток

- Лимит параллельных загрузок, отмена задачи, запись файла вне event loop (`asyncio.to_thread`), отмена задач при выходе и очистка `*.part` во всех `root` — **не сделано**, остаются в S11 (ROADMAP).
- Состояние задач живёт в памяти: после перезапуска приложения незавершённая загрузка не возобновляется (`*.part` удаляется при старте), готовые остаются.
- Подписи этапов в строке списка — в подсказке и `aria-label`; видимый текст этапа есть на кнопке страницы трека и в тостах.
- WIN-14 на Windows не выполнялся; поведение `os.replace` и путей проверено тестами на Linux и (после прогона CI) на `windows-latest`.
