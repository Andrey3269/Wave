## 1. История этапа и коммиты

Сначала S5 был сделан в строгом варианте: YouTube — только видео под лицензией Creative Commons, SoundCloud — только при `downloadable` автора и через исходный файл. Владелец отменил этот вариант: он не соответствует требованию сохранить прежнее скачивание. Код строгого варианта заменён; общие улучшения (M8, N3, этапы и прогресс в UI, тесты загрузчика) сохранены.

## 2. Что переиспользовано без переписывания

`backend/downloads.py` остался основой; сохранено прежнее поведение:

- задача в памяти с опросом `/api/downloads/jobs`, состояния `preparing → downloading → processing → done | error`;
- аудио порциями по 4 МБ с `Range` через тот же `stream._connect`, что у плеера (кэш ссылок, перерезолв протухшей ссылки посреди загрузки), источник без Range (200), неизвестный размер (`Content-Range */*`);
- исходный формат потока без перекодирования (`.m4a`, `.mp3`, `.webm`, `.ogg`), ffmpeg не нужен и не добавлен;
- обложка только с разрешённых https-хостов; текст из LRCLIB; пустой `lyrics.json` не создаётся;
- сборка папки в `*.part` и перенос целиком (`os.replace`), очистка `*.part` при старте;
- запись в SQLite, повторный запрос для скачанного → сразу `done`, для активной задачи → та же задача;
- имя папки `Artist - Title [source-id]`; воспроизведение скачанного тем же `/api/stream/{source}/{id}` с диска;
- `metadata.json` — прежний формат, без новых полей.

## 4. Правило скачивания и его границы

| Ситуация | Результат | Код |
|---|---|---|
| Поток трека `yt` или `sc` штатно получен | скачивается этот поток в исходном формате | — |
| Трек удалён, приватный, ограничен по возрасту, только HLS | отказ с той же причиной, что у плеера | `unavailable`, `age_restricted`, `no_direct_stream` |
| SoundCloud отдаёт лишь фрагмент (Go+) | отказ: фрагмент не сохраняется под видом полного трека | `preview_only` |
| Проверка на бота, лимит запросов, сеть, сбой извлечения | временная ошибка, можно повторить | `bot_check`, `rate_limited`, `network`, `extractor`, `js_runtime` … |
| Трек уже скачан | сразу `done`, играет с диска без источника | — |

**Чего нет и не добавлялось:** входа в аккаунты, cookies по умолчанию, обхода DRM, платного доступа (Go+), возрастных ограничений и антибот-проверок. Используется только тот механизм получения потока, который уже применяется для воспроизведения (yt-dlp с закреплённым Deno для JS-задач YouTube, как принято на S3).

**Это не разрешение платформ.** Wave сохраняет тот же поток, который воспроизводит. Это не означает, что YouTube, SoundCloud или правообладатели разрешили скачивание: условия YouTube запрещают скачивание, кроме явно разрешённого сервисом, условия SoundCloud ограничивают сохранение контента вне его функций. Функция реализована по решению владельца для личного использования в его приложении и не является официально одобренной интеграцией. Перед публичным распространением вопрос нужно оценить отдельно.

## 6. Ограничения и остаток

- **Правовые условия** — §4: функция не является разрешением платформ; публичное распространение требует отдельной оценки.
- Неофициальные интерфейсы (`ytmusicapi`, внутренние методы yt-dlp для SoundCloud) могут перестать работать без предупреждения — тогда перестанут работать и воспроизведение, и загрузка; обновление yt-dlp — отдельным коммитом с LIVE-2 и LIVE-8.
- YouTube может требовать подтверждения «не бот» (так было в этой облачной среде до использования прокси) — загрузка тогда заканчивается временной ошибкой `bot_check`; обхода нет.
- Треки SoundCloud Go+ не скачиваются (`preview_only`); в поиске они и раньше скрыты (`main.py`, policy `SNIP`).
- Лимит параллельных загрузок, отмена задачи, запись файла вне event loop, отмена задач при выходе и очистка `*.part` во всех `root` — **не сделано**, остаются в S11.
- Незавершённая загрузка после перезапуска не возобновляется (`*.part` удаляется при старте), готовые остаются.
- WIN-14 на Windows не выполнялся; `os.replace`, пути и API загрузок проверены тестами на Linux и `windows-latest` в CI.

```bat
python -m pytest -m live -rP tests\live\test_live_downloads.py
```
