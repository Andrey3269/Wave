## 1. Изменения

**Схема SQLite v3** (`backend/persistence/migrations.py`): новые таблицы `favorite_items (kind 'album'|'artist', source, item_id, data, added_at, PK (kind, source, item_id))` и `local_tracks (id, title, artist, album, duration, ext, size, sha256 UNIQUE, created_at)`. Прежние таблицы и строки не меняются; перед обновлением — копия `backups/wave-<дата>-v2.db`, все шаги одной транзакцией, сбой — откат. Wave S14 базу v3 не откроет (понятная ошибка); откат — из этой копии.

**API** (изменяющие запросы защищает OriginGuard S13):

| Запрос | Что делает |
|---|---|
| `GET/POST /api/library/albums`, `DELETE /api/library/albums/{source}/{id}` | альбомы в коллекции; карточка проверяется: id как в каталоге, обложка из разрешённого списка, строки без управляющих символов, год — 4 цифры |
| `GET/POST /api/library/artists`, `DELETE /api/library/artists/{source}/{id}` | исполнители в коллекции, те же проверки |
| `PATCH /api/playlists/{pid}/tracks/order` | `{"keys": ["source:id", …]}` — каждый видимый трек ровно один раз; дубль или чужой трек → 400, не все треки → 409; позиции пишутся одной транзакцией. Строки, которые GET пропускает (S13), остаются после видимых |
| `DELETE /api/history/{source}/{id}` | убирает одну запись «Недавно слушали» (все прослушивания и пропуски этого трека), остальная история не меняется |
| `GET /api/library/export`, `POST /api/library/export/file` | JSON (`format: wave-library`, `version: 1`): избранное (треки, альбомы, исполнители) с датами, плейлисты с порядком и датами, настройки. Без папки загрузок, истории, состояния плеера и путей. Файл — в папку загрузок под именем `wave-library-<дата>.json`, существующий не перезаписывается (окно WebView2 не сохраняет скачивания браузера) |
| `POST /api/library/import` | до 20 МБ; весь файл проверяется до записи (формат, версия, типы, пределы, даты, дубли, каждый трек как `TrackIn`, каждая настройка как в `PUT /api/settings`, `downloads_dir` не принимается); запись — одна транзакция. Слияние: уже избранное не меняется, такой же плейлист (имя и треки по порядку) пропускается, настройки заменяются |
| `GET/POST /api/library/local`, `DELETE /api/library/local/{id}` | локальная музыка, см. ниже |

**Источник `local`** (`backend/localmusic.py`, `streaming/router.py`; `Track.source` теперь `yt | sc | local`, аддитивно):
- импорт — копия файла: интерфейс выбирает файл системным диалогом (`<input type="file">`) и отправляет его байты (`POST /api/library/local?name=…&duration=…`). Пути с компьютера пользователя API не принимает вообще; копия — `<data>/local/<16 hex><ext>`;
- имя файла — только подпись: каталоги отбрасываются, «Исполнитель - Название» разбирается, иначе «Неизвестный исполнитель»; длительность — от браузера;
- формат по сигнатуре (ID3/MPEG, ftyp, OggS, fLaC, RIFF/WAVE, EBML) и совпадение с расширением (`.mp3 .m4a .ogg .oga .opus .flac .wav .webm .weba`), иначе 415; не больше 1 ГБ (413), пустой — 400; тот же файл (SHA-256) второй копии не создаёт;
- воспроизведение — `/api/stream/local/{id}` (Range 200/206/416, HEAD, `?warm=1` → 204, `nosniff`), `/playback` → `kind: local`; путь строится из id и расширения из белого списка, ссылки и выход из каталога не обслуживаются;
- удаление — запись, избранное и плейлисты одной транзакцией, затем копия с диска; оборванные импорты и копии без записи убираются при старте; история не меняется;
- скачивание и «Не рекомендовать трек» для `local` — 422; локальный трек без исполнителя не сигнал рекомендаций; YouTube Music и SoundCloud не затронуты.

**Интерфейс** (`frontend/js/views/library.js` новый, `collection.js`, `menu.js`, `settings.js`, `detail.js`, `index.html`, немного CSS):
- «Коллекция»: поле «Найти в коллекции» (треки из «Нравится» и локальные, альбомы, исполнители, плейлисты — по уже загруженным данным) и фильтры «Всё / Треки / Альбомы / Исполнители / Плейлисты»; разделы «Альбомы» и «Исполнители»; плитка «Локальная музыка»;
- «В коллекцию» на страницах альбома и исполнителя;
- «Локальная музыка»: «Добавить файлы» (несколько сразу), значок «Локальный файл», без кнопки загрузки, в меню — «Удалить из Wave» с подтверждением;
- меню трека: «Переместить выше/ниже» в плейлисте (при сортировке «по умолчанию»; фокус остаётся на треке, позиция объявляется через `aria-live`), «Удалить из истории»;
- настройки → «Данные»: «Экспорт в файл», «Импорт из файла…» с подтверждением и итогом.

## 2. Целевой security-review (JSON и локальные файлы)

Проведён один раз по коду этапа. Найдено и исправлено: ответы локальных файлов без `X-Content-Type-Options: nosniff` (`5a21e97`); результат импорта затирался обновлением экрана настроек (UX, найдено e2e). Проверено, без замечаний:

| Угроза | Защита |
|---|---|
| Обход каталогов, чужие файлы | API не принимает путей; имя файла — подпись; файл называется `id + ext` (id — 16 hex от сервера, ext — белый список); при чтении id и ext проверяются заново, ссылки и выход за `<data>/local` не обслуживаются; уборка при старте — только файлы с нашим шаблоном имени (`test_local_music`: `../`, `..\`, абсолютные пути, подмена `ext` в базе, symlink) |
| Не аудио под видом аудио | сигнатура + совпадение с расширением; ADTS/EXE/WAV-как-mp3 → 415 |
| Переполнение диска и памяти | 1 ГБ (по Content-Length и по факту потока), запись порциями по 1 МБ в потоке, `.part` удаляется при ошибке и при старте |
| Вредный JSON | 20 МБ; `NaN/Infinity`, нечисловые даты, огромные числа, глубокая вложенность → 400; `extra=forbid`; пределы количества; дубли → 400; URL из файла проходят те же списки, что снимки S13 (обложка/ссылка → null, `stream_url` вычисляет сервер); `downloads_dir` из файла не принимается |
| Частичная запись | проверка всего файла до записи + одна транзакция (`test_invalid_file_is_rejected_atomically` — 20 видов ошибок, `test_failure_during_write_rolls_back`) |
| CSRF, чтение с чужого сайта | изменяющие запросы — OriginGuard; CORS только GET для своего origin, TrustedHost; экспорт не содержит путей |
| SQL | только параметризованные запросы |

Остаточный риск: длина строк в снимке трека (`TrackIn`) не ограничена — как и в `POST /api/favorites` до S15; при импорте её ограничивает размер файла 20 МБ.

## 5. Ограничения

- Теги файлов (ID3 и т. п.) не читаются: название и исполнитель — из имени файла, обложки у локальных треков нет. Переименовать локальный трек в интерфейсе нельзя.
- Импорт копирует файл в `<data>/local`: место на диске удваивается, исходный файл Wave не трогает. Папки целиком не импортируются, только выбранные файлы.
- Аудиофайлы в экспорт не входят: на другом компьютере локальные треки из избранного и плейлистов пропускаются (счётчик в итоге импорта).
- Удаление записи истории убирает все прослушивания этого трека (экран истории показывает трек один раз).
- Перестановка в плейлисте — по одной позиции через меню (перетаскивания мышью нет).
- Диалог выбора файлов и экспорт в окне WebView2 автоматически не проверялись (CI — Chromium).
- Откат на S14 после обновления — только из резервной копии v2.
