## 4. Установщик `installer/wave.iss`

- `AppId={314C4533-1390-4F2A-B0B8-7003E0F6F200}` — не меняется никогда (закреплён тестом).
- `PrivilegesRequired=lowest`, без возможности переключить на установку для всех; `DefaultDirName={localappdata}\Programs\Wave`; `ArchitecturesAllowed`/`InstallIn64BitMode=x64compatible`; `MinVersion=10.0`. Манифест установщика — `asInvoker`.
- `[Files]` — вся `dist\Wave` рекурсивно; `THIRD_PARTY_NOTICES.txt` дополнительно рядом с `Wave.exe`. Компиляция останавливается, если нет `Wave.exe`, `_internal\runtime\deno`, лицензий или bootstrapper.
- Ярлык в «Пуске», по желанию — на рабочем столе. Русский и английский интерфейс.
- **Обновление:** `[InstallDelete]` удаляет только `{app}\_internal` перед копированием (остатки прошлой сборки PyInstaller не смешиваются с новой).
- **Удаление:** нет `[UninstallDelete]`, `[Code]` ничего не удаляет; `%LOCALAPPDATA%\Wave` и папка загрузок установщику неизвестны.
- **`AppMutex=Local\Wave.Desktop.SingleInstance`** — тот же mutex, что создаёт `launcher.single_instance()` (константа `SINGLE_INSTANCE_MUTEX`, сверяется тестом). Без префикса и с `Local\` это один объект пространства имён сеанса. Проверено в CI: при запущенной ВОЛНЕ установщик находит её и пишет в журнал «Setup has detected that ВОЛНА (Wave) is currently running. Please close all instances…». Интерактивно это сообщение с просьбой закрыть программу; **в тихом режиме (`/VERYSILENT /SUPPRESSMSGBOXES`) установка и удаление отказываются с кодом 1 и ничего не меняют** — программа продолжает работать. Автоматически закрывать ВОЛНУ установщик не пытается: это решение пользователя, а AppMutex его не принимает. `SetupMutex` не даёт запустить два установщика; `CloseApplications=yes` (Restart Manager — запасной путь, если пользователь нажал OK, не закрыв программу), `RestartApplications=no`.
- **Single-instance приложения и `AppMutex` — разные механизмы:** первый не даёт второму `Wave.exe` запустить backend (WIN-4), второй не даёт установщику менять файлы запущенной программы.
- **Подпись:** только при заданной `WAVE_SIGN_COMMAND` (`SignTool`, подписываются установщик, деинсталлятор и `Wave.exe`). Без неё — без подписи. Путь с подписью не проверялся (сертификата нет).

### WebView2

- Обнаружение — ровно по `launcher.WEBVIEW2_KEYS`: `HKLM\SOFTWARE\WOW6432Node\…`, `HKLM\SOFTWARE\…`, `HKCU\Software\…\EdgeUpdate\Clients\{F3017226-…}`, значение `pv` не пустое и не `0.0.0.0` (совпадает с рекомендацией Microsoft). Списки сверяет тест.
- Нет WebView2 → после копирования файлов официальный `MicrosoftEdgeWebview2Setup.exe /silent /install` (без прав администратора Microsoft ставит его для текущего пользователя), ожидание завершения, **итог решает повторная проверка реестра**, а не только код выхода.
- Сбой → сообщение на русском (что случилось, проверить интернет и повторить, ссылка Microsoft, администратор), галочка «Запустить ВОЛНУ» не показывается, тихая установка завершается кодом **100** («программа установлена, WebView2 нет»; коды 1–8 заняты Inno Setup). Программа при этом установлена, и сама при запуске показывает сообщение о WebView2 со ссылкой (`launcher.py`, без изменений).
- Тестовый вариант `/DTestWebView2=ok|fail` (только CI): WebView2 считается отсутствующим, вместо bootstrapper — `cmd /c exit 0|1603`. Код под `#ifdef`, выпускаемый установщик его не содержит (тест проверяет вложенность директив; CI — что журнал выпускаемого установщика не содержит `TEST MODE`).
- `packaging/fetch_webview2.ps1`: создаёт каталог до загрузки (причина сбоя ручной сборки S3), скачивает по официальной ссылке Microsoft и принимает файл только с действительной подписью Authenticode `O=Microsoft Corporation`; закреплённого SHA-256 нет и не выдумывался (Microsoft обновляет файл по той же ссылке). Хэш печатается для отчёта. Файл кладётся в `build\webview2\` (не в исходники).

## 7. `WAVE_PORT` и второй запуск

`WAVE_PORT` читается только из окружения; значение — ASCII-цифры 1024–65535, иначе запуск останавливается с понятным сообщением до создания окна. Занятый порт — ошибка (и в сторожевом перезапуске), а не молчаливый выбор другого: тест ждёт именно этот порт. Сокет по-прежнему только `127.0.0.1`, `TrustedHostMiddleware` и CORS не менялись. Без переменной — прежний свободный порт.

Второй запуск: поведение не менялось (mutex `Local\Wave.Desktop.SingleInstance`, сообщение «Wave уже запущен.», backend не стартует), добавлена строка журнала. Отдельного дефекта не найдено; известное ограничение L5 (окно первого экземпляра не активируется) остаётся на S17.

## 10. Найдено и исправлено по ходу

1. Сборка у владельца в S3 ушла на Python 3.14 из-за запасного `py -3` — убрано, 3.12 обязателен.
2. Каталог `installer\` для bootstrapper не создавался — bootstrapper теперь в `build\webview2\`, каталоги создаются до загрузки.
3. `Wave.exe --diagnostics` при сборке писал журнал и кэш Deno в настоящий профиль пользователя — теперь временный профиль.
4. В приложение попадали PyInstaller.utils, setuptools, pefile, altgraph, pywin32-ctypes (через хуки pythonnet/pywebview) — исключены, размер `dist\Wave` 148,7 → 147,1 МБ.
5. Тесты лаунчера на Windows показывали настоящий MessageBox и ждали 90 с — headless-режим в тестах.
6. Скрипт проверок: имена переменных PowerShell не различают регистр (`$status`/`$Status`); процесс другого пользователя наследует `TEMP`/`USERPROFILE` раннера; ярлык с кириллическим именем не читается через WScript.Shell — исправлено.

## 11. Ограничения

- Интерактивная часть WIN-2/3/4/8/9 и сборка на вашей машине не выполнялись (нет Windows с экраном).
