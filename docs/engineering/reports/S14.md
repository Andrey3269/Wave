## 1. Изменения

**Схема SQLite v2** (`backend/persistence/migrations.py`): таблица `rec_exclusions (kind 'track'|'artist', value, label, created_at, PK (kind, value))`. Только новая таблица, прочие не меняются; перед обновлением — резервная копия `backups/wave-<дата>-v1.db`. Ограничение: Wave S6–S13 базу v2 не откроет (понятная ошибка «база от более новой версии»); откат — через эту копию.

**API** (`backend/recs.py`, `backend/recs_store.py`; изменяющие запросы защищает OriginGuard S13):

| Запрос | Что делает |
|---|---|
| `GET /api/recommendations/exclusions` | `{items: [{kind, value, label, created_at}], reset_at}` |
| `POST /api/recommendations/exclusions` | `{kind: "track", source, id, title, artist}` или `{kind: "artist", artist}`; id в формате источника, иначе 422; повтор не создаёт дубль; предел 5000 → 400 |
| `DELETE /api/recommendations/exclusions/{kind}/{value}` | вернуть в рекомендации |
| `POST` / `DELETE /api/recommendations/reset` | сброс сигналов / отмена сброса |

Исполнитель исключается по нормализованному имени (регистр и знаки не различаются, YouTube Music и SoundCloud одинаково, учитываются соавторы); исключённый не ищется даже из избранного. Исключение и сброс не меняют историю, избранное, плейлисты и загрузки.

**Сброс сигналов** — отметка `recs_reset_at` (служебная строка `settings`, в `/api/settings` её нет, `PUT` её не принимает): прослушивания, пропуски и избранное до отметки не влияют на баллы, записи остаются, сброс отменяется. Защита от повторов и исключения при сброшенных сигналах продолжают действовать.

**Алгоритм** (ответ `/api/recommendations` прежний, у трека добавлено поле `reason_kind`):
- запись-пропуск (S10) больше не считается прослушиванием исполнителя — раньше пропуск давал исполнителю +5 и поиск по нему;
- исполнитель только с пропусками (≥ 3, ни одного прослушивания, не в избранном) не предлагается; пропускаемый чаще, чем слушаемый, — штраф −10 за пропуск, не ниже −30;
- не больше 2 треков одного альбома (по `album_id`, иначе название + исполнитель); недавно игравшая песня (последние 25 записей) не предлагается и на другом видео; +4 за нового исполнителя, только когда есть история или избранное;
- причина по самому треку: «Любимый исполнитель» / «Из твоей истории» — только если это правда для его исполнителя; чужой трек из поиска по исполнителю — «Найдено поиском по исполнителю X»; холодный старт — «Подборка по запросу «…»»; `reason_kind`: `radio | fav_artist | history_artist | artist_search | general`.

**Интерфейс:** в меню трека «Не рекомендовать трек» и «Не рекомендовать исполнителя» (карточки сразу уходят из ленты, фокус клавиатуры — на вставшую на место); под исполнителем на карточке ленты — причина; в настройках раздел «Рекомендации» (состояние, «Сбросить персонализацию» с подтверждением, «Вернуть прежние сигналы», список «Не рекомендовать» с «Вернуть»); заголовок ряда «Новое для тебя» → «Ещё из подборки»; фильтр «Похожих» на странице трека — по `reason_kind`.

## 2. Офлайн-оценка

`tests/wavetest/recs_eval.py` — 4 детерминированных сценария истории, проигрываемых через настоящий API с двойником ytmusicapi; метрики не зависят от кода рекомендаций. Базовая линия посчитана тем же тестом на backend `37781f8` (`tests/fixtures/recs_eval/baseline.json`); `tests/api/test_recs_eval.py` требует не хуже по каждой метрике и не меньше 3/4 треков без повторов.

| Сценарий | Треков | Доля новых исполнителей ↑ | Доля повторов ↓ | Доля пропусков ↓ |
|---|---|---|---|---|
| loyal (3 исполнителя, повторы на других видео) | 12 → 9 | 0,25 → 0,33 | 0,50 → 0 | 0 → 0 |
| skipper (исполнителя постоянно пропускают) | 17 → 14 | 0,47 → 0,57 | 0 → 0 | 0,18 → 0 |
| radio_album (сборник и дубли в радио) | 20 → 13 | 1,0 → 1,0 | 0 → 0 | 0 → 0 |
| cold (холодный старт) | 15 → 15 | 1,0 → 1,0 | 0 → 0 | 0 → 0 |

Регрессий нет. Меньше треков — это убранные повторы, пропускаемый исполнитель и лишние треки сборника: в loyal треков без повторов 6 → 9. Персонализация по-прежнему не подтверждена на реальных данных — поэтому «Ещё из подборки».

## 5. Ограничения

- Метрики — на синтетических фикстурах; на реальной истории пользователя персонализация не измерялась.
- Нормализация имени во фронтенде (`core/exclusions.js`) близка к Python `\W`, но не тождественна для редких символов; это влияет только на мгновенное скрытие карточек, выдачу фильтрует backend.
- Исключение исполнителя — по имени: разные исполнители с одинаковым именем исключаются вместе.
- Откат на S6–S13 после обновления — только из резервной копии v1.
- Сигналы и исключения влияют на ленту, «Похожие», миксы и продолжение очереди (все идут через `/api/recommendations`); очередь, уже собранная до исключения, не меняется.
