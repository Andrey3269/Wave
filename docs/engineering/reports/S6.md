## 3. Изменённое поведение

**Хранилище.**
- Многошаговые операции атомарны; одиночный запрос сразу виден другим соединениям.
- WAL: рядом с `wave.db` появляются `wave.db-wal` и `wave.db-shm` (при закрытии последнего соединения SQLite переносит журнал в основной файл). Сбой посреди записи не портит базу.
- `foreign_keys=ON`: каскадное удаление треков плейлиста работает на уровне базы; добавление в удалённый плейлист → 404, а не «висячая» строка. Старые «висячие» строки, если есть, не удаляются (это данные пользователя).

**Миграции и копии.**
- База без версии (`5a7f27c`, S0–S5 и старше) → копия → v1 одной транзакцией → проверка таблиц и колонок → `user_version = 1`. Повторные запуски ничего не меняют и копий не делают.
- Копия: `<data>/backups/wave-<ГГГГММДД-ЧЧММСС>-v<N>.db`, N — версия схемы **в копии** (для баз до S6 — `v0`). Совпадение имени → `-2`, `-3`, существующая копия не перезаписывается. Пишется в `.part`, проверяется `PRAGMA quick_check`, затем переименовывается; хранятся три последние, чужие файлы в папке не трогаются. Пустой файл (новая установка) обновляется без копии.
- Не удалось сделать копию → база не меняется, приложение не стартует. Сбой обновления → откат схемы, данных и `user_version`, WAL не включается, приложение не стартует. База от более новой Wave (`user_version` > 1) или повреждённый файл → не открывается и не меняется. Во всех случаях окно показывает «Wave не смог открыть базу данных» с причиной, текст пишется в журнал.
- База v1 открывается и версиями до S6: их `CREATE TABLE IF NOT EXISTS` и `ALTER … root` в `try` проходят (проверено тестом).

**M5.** Повторное и одновременное добавление одного трека → `{"added": false}`, без `IntegrityError`/HTTP 500; позиции без повторов, новый трек — в конец; сохранённый порядок и «дырки» в позициях старых плейлистов не трогаются.

**M6.** `explicit`, `plays`, `released` сохраняются в избранном, истории и плейлистах; старые снимки без них читаются как есть. В «Нравится», истории и плейлистах теперь появляются сортировки «Популярные» и «Новые», если источник даёт эти данные (SoundCloud); раньше поля терялись при сохранении. Запись с «/» в `id` удаляется (и закодированным `%2F`, как шлёт фронтенд, и как есть). Проверка формата `id` на входе — S13.

**История.** Хранятся последние `history_limit` записей (по умолчанию 10 000, допустимо 1 000–100 000, только целое; мусор в базе → значение по умолчанию). Обрезка — в той же транзакции, что запись прослушивания, при уменьшении лимита и при запуске. Удаляются только старые строки `history`. Рекомендации читают 300 последних — не затронуты. Отдельного UI для лимита нет (только `/api/settings`): экран настроек — этап S18.

## 6. Оставшиеся риски

- **Одна блокировка на всё приложение.** Для одного пользователя достаточно, но долгий запрос задерживает остальные. Вызовы индекса загрузок из async-кода `downloads.py` по-прежнему блокируют event loop на время запроса (было и до S6; отдельный поток — S11).
- **Соединение не закрывается при остановке backend** — намеренно: фоновые загрузки, ещё не отменяемые до S11, могут записать индекс после выхода из `lifespan`. WAL надёжно восстанавливается при следующем открытии; `-wal` может остаться до следующего запуска.
- **База от более новой Wave блокирует запуск** (до установки последней версии). Это защищает данные, но требует от пользователя действия; откат на версию до S6 база v1 не ломает.
- **Копия базы — только перед миграцией**, не при каждом запуске. Резервирование пользовательских данных в целом (экспорт, расписание) — отдельная функция библиотеки.
- **Восстановление из копии — вручную** (описано в README). Копирование одного `wave.db` при открытом приложении может не захватить последние записи из `-wal`.
- `foreign_keys=ON`: существующие «висячие» строки плейлистов не удаляются и не видны; новых не появится.
- Формат `id` на входе не проверяется (M6, часть S13); удаление записей с «/» теперь возможно.
- Обрезка истории на каждой записи проходит индекс первичного ключа до лимита (10 000 шагов) — на тестах незаметно, на слабом ПК не измерялось.

## 7. Обязательные ручные проверки (Windows 11, владелец)

1. Установить сборку S6 поверх установленной S4/S5 с настоящим профилем, где есть избранное, история, плейлисты, настройки и скачанные треки.
2. Первый запуск: всё на месте; в `%LOCALAPPDATA%\Wave\backups\` появился `wave-<дата>-v0.db`; рядом с `wave.db` — `wave.db-wal`/`wave.db-shm` (пока Wave открыта).
3. Закрыть и открыть снова: новых копий нет, данные те же.
4. Добавить один трек в плейлист дважды (быстро двойным кликом в меню) — ошибки нет, трек один. Удалить трек из плейлиста, удалить плейлист.
5. Лайкнуть трек SoundCloud с числом прослушиваний — в «Нравится» в списке сортировки есть «Популярные» и «Новые», в строке трека — число прослушиваний; после перезапуска всё на месте.
6. (По желанию) открыть ту же папку данных прежней версией Wave (S5) — запускается, данные на месте.
