# S10 — ручная проверка на Windows 11 (WebView2): очередь, плеер, медиаклавиши (WIN-11)

Ручной чек-лист владельца для приёмки S10. **Результат зафиксирован 2026-10-16: владелец подтвердил прохождение всех 15 пунктов (PASS).**

Автоматические проверки этого не заменяют. e2e и браузерные pytest-тесты идут в **Chromium из Playwright**, а не
в окне **WebView2**, и не нажимают физические медиаклавиши: Media Session там проверяется вызовом обработчиков,
которые зарегистрировало приложение (`tests/e2e_smoke.py`, раздел «Media Session»). Только здесь видно, что
медиаклавиши клавиатуры/гарнитуры и системный оверлей Windows (всплывающая панель управления мультимедиа)
действительно управляют ВОЛНОЙ, и что очередь переживает настоящее закрытие окна приложения.

**Сборка.** Ветка `claude/s10-queue-player`, `build_windows.bat` (или установщик из артефакта CI `windows-build`).
Версия приложения не менялась (0.1.0) — установщик ставится поверх как обновление. Перед началом: закрыть Wave,
сохранить копию `%LOCALAPPDATA%\Wave` (база `wave.db` остаётся схемы v1: S10 не меняет схему).

**Что поменялось для пользователя (для ориентира).** Кнопка повтора переключает три режима: выкл → вся очередь →
текущий трек (значок с «1»). Перемешивание не повторяет треки до конца круга, «Назад» идёт по фактическому
порядку. Очередь, трек, позиция и режимы восстанавливаются после перезапуска **без автозапуска звука**. Трек
попадает в историю после 30 с или половины длительности. «Открыть альбом» у треков YouTube Music — сразу по
альбому. Без сети вместо перехода в «Скачанные» — сообщение с кнопкой.

## Результат

**PASS — 15/15 пунктов.** Владелец подтвердил прохождение всех проверок на Windows 11 с WebView2 2026-10-16. Автоматические проверки Media Session в Chromium остаются отдельно описаны в `reports/S10.md`.
