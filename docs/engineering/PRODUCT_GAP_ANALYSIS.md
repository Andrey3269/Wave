# Продуктовый gap-анализ «ВОЛНА»

Основа: [REPOSITORY_AUDIT.md](REPOSITORY_AUDIT.md) (коммит `5a7f27c`). Приоритеты:

- **P0** — нужно для честного и работоспособного выпуска и для безопасного дальнейшего развития;
- **P1** — качество основных сценариев;
- **P2** — развитие продукта и дифференциация.

Статусы функций:

- **работает** — подтверждено e2e-тестом (с моками внешних источников) или пробой;
- **частично** — код есть, но не проверен на живых источниках или имеет известные ограничения;
- **нет** — отсутствует.

## 1. Принципы

1. **Честность.** Подборка называется тем, чем она является. Нет фиктивной персонализации, трендов, счётчиков и «новых имён», если источник таких данных не даёт.
2. **Своя идентичность.** Яндекс Музыка, Spotify, SoundCloud и YouTube Music — только ориентиры по сценариям. Их фирменные названия функций, визуальные элементы и тексты не используем.
3. **Изоляция источников.** Сбой одного источника не ломает другой и не трогает локальную библиотеку. Пользователь видит понятную причину.
4. **Соблюдение условий платформ.** Возможность включается, только если это допускают условия источника. Нет обходов DRM, авторизации, лимитов и региональных ограничений.
5. **Данные пользователя неприкосновенны.** Ни одно изменение не удаляет избранное, историю, плейлисты и скачанные файлы без явного действия пользователя.

## 3. Названия подборок: решение владельца и предложения

Решение: фирменные названия конкурентов не копируем. До появления настоящего алгоритма персонализации используем описательные названия.

| Место (код) | Сейчас | Что это на самом деле | Предложение (финальный текст утверждает владелец) |
|---|---|---|---|
| Баннер главной, eyebrow и заголовок (`app.js:983, 993`; `index.html:73, 138-151`) | «Моя волна» | лента `/api/recommendations`: радио текущего трека, поиск по любимым артистам, при холодном старте — общие запросы | «Подобрано по вашей истории»; при холодном старте — «С чего начать» |
| Кнопка «Слушать волну» (`app.js:999`; `index.html:158`) | «Слушать волну» | запуск этой ленты | «Слушать подборку» |
| Заголовок ряда миксов (`index.html:180`) | «Под твою волну» | радио по недавним трекам плюс тематические поиски | «Миксы по вашим трекам» |
| Подпись очереди (`app.js:492, 974`) | «Моя волна» | то же | «Подборка для вас» |
| Тематический микс `discover` (`app.js:675`) | «Открытия недели · Новые имена и свежие треки» | поиск по запросу `новинки <год>` | «Новинки года» · «Поиск по запросу «новинки 2026»» |
| Микс `shake` (`app.js:676`) | «Встряхнуть мою волну» | случайная страница рекомендаций | «Другая подборка» · «Новая выборка из рекомендаций» |
| Флаг `personalized` (`recs.py:178`) | `true` уже при наличии текущего трека | — | `true` только при наличии истории или избранного; радио трека отдельным полем |
| Заголовок ряда ленты (`index.html`, «Новое для тебя») | «Новое для тебя» | продолжение той же ленты `/api/recommendations`; при холодном старте — общие запросы | **«Ещё из подборки»** — решение владельца 2026-10-13, этап S14 или S18; персональное название — только после подтверждения персонализации данными |

Статус: строки выше, кроме последней, реализованы в S2e (`4df5b50`) и `personalized` в S2c (`21ddcab`); тексты утверждены владельцем 2026-10-13.

Совместимость. `tests/e2e_smoke.py:176` ждёт загрузки ленты по признаку «`#hero-title` перестал быть «Моя волна»». Если поменять заголовок-заглушку без правки теста, условие станет истинным сразу, и тест начнёт «мигать». Условие нужно перевести на явный признак готовности, например `#hero` с `data-state`, отличным от загрузки, или непустой `#new-grid`. Подписи «Пауза», «Продолжить» и «Сейчас играет» (строки 192, 195, 200) не меняются. Тексты и тест правятся одним коммитом, число проверок не уменьшается.

Собственная персональная функция под брендом «ВОЛНА» (рабочее название утверждает владелец) появится только на этапе S14, после измеримых улучшений рекомендаций. Слово «Волна» как часть бренда приложения допустимо. Нельзя называть так ленту так, чтобы это совпадало с названием функции конкурента.

## 4. Политика источников и скачивания (этап S5)

Решения владельца от 2026-10-12 (ADR-5, ADR-6). Политика применяется на backend, обойти её прямым API-запросом нельзя.

| Возможность | `yt` | `sc` | Локальные файлы |
|---|---|---|---|
| Поиск, метаданные, потоковое воспроизведение | включено; риск по условиям YouTube зафиксирован в аудите §5 | **выключено** в распространяемой версии до подтверждения допустимости сценария; адаптер сохраняется за интерфейсом | да |
| Скачивание новых треков | **выключено** до подтверждения допустимого способа доступа | **выключено** | не применимо |
| Воспроизведение уже скачанного | **сохраняется**, файлы не удаляются | **сохраняется** (локальные данные пользователя) | да |
| Импорт собственных файлов | — | — | разрешён, не блокируется политикой (S15) |

Что не считается основанием включить SoundCloud: само по себе получение `client_id`; раздельные очереди по источникам. Включение возможно только отдельным решением владельца после проверки применимых условий для конкретного сценария.

UX при недоступности возможности:
- кнопка «Скачать» не исчезает молча, а заменяется пояснением: «Этот источник не разрешает сохранять треки на устройство»;
- SoundCloud в переключателе источников помечен «недоступен в этой версии»;
- ошибки источника показываются человеческими текстами по типам: недоступен, таймаут, ограничение по региону или возрасту, требуется вход, лимит запросов;
- технические детали уходят в журнал.
